# Система команд терминала «Электроника МС 7401»

Справочник составлен по коду эмулятора: `mc7401/constants.py`
(коды и палитры), `mc7401/parser.py` (грамматика), `mc7401/emulator.py`
(семантика), `mc7401/reader.py` (протокол ВУК), `mc7401/chars.py`
(шрифты), `mc7401/link.py` (ДКС). Источник по устройству — статья
«Дисплейные микроконтроллеры семейства МИДИКОН», МПСС, 1989, № 5,
стр. 38-43.

---

## 1. Физические коды

| Символ | Код | Где применяется |
|---|---|---|
| `ВК` | 0o125 (85, `'U'`) | разделитель записей потока |
| `АР2` | 0o124 (84, `'T'`) | префикс управляющих маркеров кадра |
| `S0` | 0o160 | переключение на русский шрифт |
| `S1` | 0o161 | переключение на латинский шрифт |
| `LF` | 0o175 (`'}'`) | смещение окна |
| `END` | 0o377 | конец текста, конец потока |
| `0o32` | 26 (`SUB`) | заполнитель кадра, операции не несёт |
| `0o110` | 72 | начало загрузки пользовательского знака |
| `0o240` | 160 | начало строки пользовательского знака |
| `0o215` | 141 | конец пользовательского знака |
| `≠` | 0o256 | инвертирующее перо |

Записи разделены `ВК`. Параметры — через пробел. Координаты: `X`
вправо, `Y` вверх, начало в левом нижнем углу, экран 560×400 точек.
Знаки занимают знакомест 7×8.

---

## 2. Протокол ВУК (кадр)

Программа не пишет в терминал напрямую: буфер `OUTRUT` выдаётся блоками
через канал ВУК. Блок устроен так:

```
'/' ВК  'z' + 19 нулей  <данные>  АР2 'У  '  АР2 'F‾' ВК
└ начало ┘└ служебная ┘└ полезная ┘└ в кадр ┘└ конец кадра ┘
```

Порог кадрирования — 192 байта (`300В`), либо принудительно
(`ВЫД(ТR)` / `РИС(ТR)`).

Разбор потока (`reader.py`) выдаёт события:

| Событие | Содержание |
|---|---|
| `VUK_BLOCK` | `'/' ВК` — начало блока, граница выдачи |
| `COMMAND` | запись с операцией |
| `FRAME_BEGIN` | `АР2 'У  '` — вход в кадр |
| `FRAME_END` | `АР2 'F‾' ВК` — конец кадра |
| `TEXT_LINE` | `ESC 0o306 0o336 0o215` — конец строки текста |
| `DEFCHAR` | `0o110 0o240 … 0o215` — блок пользовательского знака |
| `PAD` | `0o32 ВК` — заполнитель |
| `END_OF_STREAM` | `0o377` |

В `reader.py` кроме событий есть внутренние состояния автомата
(`NORMAL`, `VUK_HEADER`, `VUK_PAYLOAD`) — наружу они не выдаются. В
`parser.py` есть ещё два значения `Op`, не являющиеся командами
терминала: `Op.FRAME_END` (конец кадра, разбирается как событие разбора)
и `Op.UNKNOWN` (запись не распознана; её код и число вхождений доступны
в `CommandParser.unknown`).

Операции графики кодятся 7-битными числами; текст — последовательностью
кодов знаков. Первая буква большинства команд — ASCII-символ.

## 3. Команды

| Команда | Синтаксис | Действие | Где в коде |
|---|---|---|---|
| `J0` | `J0` | упразднён (был «текстовый режим»), игнорируется | `Op.NOOP` |
| `J1` | `J1` | графический режим | `Op.GRAPHICS_MODE` |
| `S` | `S` | очистить экран | `Op.CLEAR` |
| `K` | `K` (кириллическая `К`, байт `0xEB`) | сброс состояния | `Op.RESET` |
| `4` | `4 X Y` | перенести текущую точку в (X, Y) | `Op.MOVE_ABS` |
| `5` | `5 dX dY` | перенести точку на (dX, dY) | `Op.MOVE_REL` |
| `7` | `7 T X Y` | провести отрезок до (X, Y), тип линии `T` | `Op.LINE_ABS` |
| `8` | `8 T dX dY` | провести отрезок на (dX, dY) | `Op.LINE_REL` |
| `]` | `] X1 Y1 X2 Y2` | прямоугольник | `Op.RECT` |
| `>` | `> T R` | окружность радиуса `R` | `Op.CIRCLE` |
| `}` | `} X Y` | смещение начала координат на (X, Y) | `Op.SHIFT_WINDOW` |
| `0` | `0 C` | установить перо/цвет `C` | `Op.SET_PEN` |
| `1` | `1 C` | установить тип линии `C` | `Op.SET_LINE_TYPE` |
| `9` | `9 S` … `;O` П1 <текст> | текст размером `S` в направлении `O` | `Op.TEXT` |
| `9:` | `9 S` … `:N` | установить размер текста `N` | `Op.SET_TEXT_SIZE` |
| `+` | `+` | режим OR (запись) | `Op.PEN_OR` |
| `≠` | `≠` | режим XOR (инвертирование) | `Op.PEN_XOR` |
| `*` | `* C` | стирание пером `C` | `Op.PEN_ERASE` |
| `3` | `3` | конец обновления экрана | `Op.UPDATE_END` |

### Перья

`constants.PEN_BY_CODE`: `OR` — запись, `ERASE` — стирание,
`XOR` — инвертирование. Четыре пера совпадают с описанными в статье
(стр. 43): рисующее, стирающее, инвертирующее,
рисующе-инвертирующее.

### Типы линий

`constants.LINE_PATTERNS`, тип `6` отключён:

| Тип | Узор |
|---|---|
| 0 | сплошная |
| 1 | сплошная |
| 2 | штриховая |
| 3 | пунктирная |
| 4 | штрих-пунктир |
| 5 | точечная |
| 6 | отключена |
| 7 | сложная |

Тип линии задаётся 8-битным «шифровым кодом» (стр. 43) — это `ГТИП`
в `golden/graf.pas`.

## 4. Текст

Текст выводится двумя записями, как это делает `ТЕКФАЙ` и `СТРОКИ`:

```
9 <размер> ВК
: <размер> ВК          ← действует до следующей установки
; <направление> П1 <коды знаков> ВК
```

* направление — код символа, 0…7 (0 — вправо, против часовой стрелки);
* размер — 0…3; нулевой означает «мелкий знак», а не отсутствие знака
  (`chars.py`, `size = max(1, size)`);
* внутри строки `S0` (0o160) и `S1` (0o161) переключают шрифт;
* `END` (0x377) обрывает строку.

Программа дописывает символы по одному (`WРИТЕ(INРUТ↑)`), поэтому
продолжения строки накапливаются и отдаются одной записью
(`reader._flush_text`).

Форма записи `;` бывает двух видов: `;O` П1 <строка> (`ТЕКФАЙ`, направление
задано) и `;` П1 <строка> (`СТРОКИ`, направления нет).

### Строки набора (`СИМВОЛЫ`)

Таблица знаков идёт строками без записей `ВК` — данные до `≡215`:

```
ESC 0o306 0o336 0o215   ← признак строки текста
0o273 0o240             ← начало строки набора
<коды знаков>           ← каждый байт — код знака как есть
≡215                    ← конец строки
≡257 ≡215 + 14 нулей     ← служебный хвост ВНУК
```

В строке набора каждый байт — код знака (в том числе `p`/`q`, чьи коды
совпадают с `S0`/`S1`); регистр переключают управляющие коды `0o16` (SO —
русский) и `0o17` (SI — латинский), как в 15ИЭ.  Блоки заказных знаков
(`≡110≡240` … `≡215`) несут код знака и семь строк по три глифа `WN`
(`chars.decode_defchar`).

### Шрифты

| Страница | Код | Содержимое |
|---|---|---|
| `S1` | 0o161 | латинская, знаки 7×8 |
| `S0` | 0o160 | русская, знаки 7×8 |

Ключ страницы — сам семибитный код: `п` = 0x70, `и` = 0x69, `т` = 0x74
(при кодах КОИ-8 0xF0/0xE9/0xF4). Это следует из семибитного формата,
подтверждённого статьёй (стр. 40), и совпадает с `native.py`,
восстановленным из `graf1.pas`.

Порядок букв КОИ-7 (ГОСТ 27463-87, ПЗУ КР556РТ5) — `ЮАБЦДЕФГХИЙКЛМНОПЯРСТУЖВЬЫЗШЭЩЧ`;
буквы пути ДКС/Н2 (`chars.koi7_label`) показываются **заглавными** в
обеих строках кодов (`0o40…0o5E` и `0o60…0o7E`): линия БЭСМ-6
регистронезависима (simh `unicode_to_koi7` складывает оба регистра в
строку `0x60…0x7F`), как и требовалось — заглавными, а не строчными.
Страница `S0` (текст графики) в регистре не менялась.

Происхождение начертаний и что в них не доказано — см.
`JOURNAL.md`, раздел «Знаки кириллицы».

## 5. Пользовательские знаки

Терминал позволяет переопределить 64 знака.  Блок описания (`СПЕЦ` в
`golden/graf.pas`):

```
0o110 0o240 <код> <0o267> <0o267>   начало загрузки, код знака
0o240 <глиф WN> × 3                 строка знака (по 3 бита на глиф)
…                                   всего 7 строк
0o215                               конец
```

Глиф `WN` — «N точек в знакоместе 3×3»: значения 0…9 кодируются
`≡060, ≡261, ≡262, ≡063, ≡264, ≡065, ≡066, ≡267, ≡270, ≡071`
(`chars.DOT_GLYPH_CODES`); строка знака собирается как
`(1-й глиф) << 6 | (2-й) << 3 | (3-й)`.  Загружает их `СПЕЦ` в
`golden/graf.pas`; разбор — `chars.decode_defchar`, таблица —
`chars.USER_TABLE`, 64 знака, каждый 7×7.

## 6. Смещение окна

`} X Y` (`LF` 0o175) — сдвиг начала координат. Рисование продолжается
в окне `[X, X + 560) × [Y, Y + 400)`; команды `НАЧГРАФ` и `СЕТ` его
сбрасывают. Состояние — `TerminalState.window`, сдвиг —
`TerminalState.window_shift`.

## 7. Связь с БЭСМ-6 по ДКС

Описано в `docs/DEPLOY.md`, раздел 4. Кратко: **ЭВМ слушает порт,
терминал подключается** (`TMXR`, `set ttyN dks,raw`, порты 4202-4223);
ЭВМ → терминал идёт поток команд, терминал → ЭВМ — ввод с
клавиатуры, эхо делает линия ДКС.

### Текст ОС Диспак на линии

Приглашение («ЭВМ-3,Т017») приходит **семибитными кодами КОИ-7**, а не
восьмибитным КОИ-8Р: строка `7C 42 4D 2D 33 2C 54 30 31 37`. Кириллица
занимает обе строки — `0x40…0x5E` (заглавные, как в наборе Н1) и
`0x60…0x7E`; цифры и знаки препинания стоят на своих местах. Латинской
строчки в КОИ-7 нет: слот `0x68` — это «Х». Разбор — `chars.display_dks()`.

Приглашение ОС запрашивается **ПРПС** (пустой строкой): ОС Диспак
отвечает на неё приглашением «ЭВМ-3,ТNNN».  Э-60 регистрируется ОС не
сразу и ранние строки проглатывает (эталон 15ИЭ: `agent.py` —
`drain()`, затем `key("KEY_ENTER")`), поэтому эмулятор повторяет
запрос с паузой, пока машина не ответит.  Само подключение приглашения
не вызывает. После подключения линия передаёт приветствие обвязки
стенда («Connected to the БЭСМ-6 simulator TTY device, line N») — это
её сообщение, а не ОС Диспак.

### Конец строки

По эталону 15ИЭ (`ie15emu/charset.py::to_line`, ветка `dks`) окончание
строки на линии ДКС — **ПР (0o015)**: `dks_line_char` завершает строку
по ПР, а `ETX` для линии — просто знак (команда с `ETX` не
выполняется — проверено на живой машине).  Настраивается настройкой
`[line] eol`: `CR` (по умолчанию), `LF`, `ETX` или восьмеричный код.

Линия всегда эхит отданные знаки (ПР — как ПС, ВК — тройкой
«ВК ПРОБЕЛ ВК»); эхо-ответ срезается из потока, чтобы набранное
не показывалось дважды.

### Передача символов

В режиме **С ЭВМ** знак уходит в линию сразу при нажатии, а `ПРПС`
(Enter) передаёт только конец строки. В режиме **АВТОНОМНО** знаки копятся
в буфере, и строка уходит по **ПЕРЕДАЧА** (`S`).

## 8. Окно терминала

Окно одно: холст — это кадр терминала 560×400, **графика и текст
вместе**, а вокруг него — служебные строки.  Отдельного текстового
режима и текстового поля нет: текст из БЭСМ-6 рисуется на кадре глифами
эталона СИМ в позиции курсора.  Растр знака ПЗУ 7×8 на кадре
увеличен вдвое — 14×16, знакомест 16×20, сетка 35×20 знакомёстов
(`[terminal] glyph`).

| Часть | Что это |
|---|---|
| строка состояния | над кадром: тип линии, ЭВМ, терминал, канал, режим, время |
| кадр 560×400 | графика и текст терминала на одном экране |
| подвал | состояния (`РЕЖИМ=`, `НАБОР=`, `ЛИНИЯ=`, `ЭХО=`, `ПЕРО=`, `БУФЕР=`, `СЕТКА=`, `МАСШТАБ=`, `ТОЧЕК=`, `КУРСОР=`, `ГРАФИКА=`, `ПОСЛ:`, `ВВОД=`), черта, легенда клавиш и последнее диагностическое сообщение |

Служебные строки нарисованы **тем же знаком**, что и текст в кадре: у
экрана одна типографика, как на настоящем терминале.  Структура подвала
— как на 15ИЭ-00-013: ячейки «метка=значение» в ровных колонках с
разделителями « | », ряды состояний отбиты от легенды чертой, легенда
идёт группами.  Кадр при этом не затрагивается — служебные строки лежат
**вне** него, как служебная строка и подвал у настоящего 15ИЭ.

**Ввод — прямо на экране.**  Стрелки или мышь ставят курсор в любой
знакомёст кадра; набираемые знаки рисуются там же глифами СИМ и уходят
на ЭВМ.  `ВК` (Backspace) стирает знакомёст слева, `ПРПС` (Enter) —
конец строки, `Escape` — отменить набор (стереть до начала строки).
Перевод строки по `ВК`, `ПС` и ETX; пара `ВК ПС` — один перевод.

**Режимы сеанса сохранены**: `СЕТЬ` (F9) переключает **АВТОНОМНО ↔
С ЭВМ**, `ПЕРЕДАЧА` (F10) уходит по линии в АВТОНОМНО, `ЭХО` (F6)
снимает показ набираемого (пароли), `НАБОР` (F8) меняет набор знаков,
`ОЧИСТКА` (F5) чистит кадр и складывает его в историю выдачи.

**Световое перо** (`ПЕРО`, F2) включает режим, в котором мышь рисует по
кадру; `F3` перебирает инструмент (штрих → точка → стирание → инверсия —
те же перо, что у команд `+`, `*`, `≠`).  Правая и средняя кнопки —
стирание.  Колесо мыши и PgUp/PgDn листают историю выдачи.

Графическое окно открывается **по умолчанию** (без аргументов и при
`--link`); `--tui` — текстовый интерфейс в консоли.  Адрес линии
берётся из `[line] endpoint`, если `--link` не задан.  Служебные
надписи масштабируются вместе с кадром (`--scale`).

**Показ графики** задаётся `[display] graphics` или `--graphics`:

| Значение | Как показывается |
|---|---|
| `auto` | протокол графики терминала, если он есть; иначе псевдографика |
| `kitty` | требовать протокол; без него — сообщение об ошибке |
| `blocks` | всегда половинные блоки `▀▄█` |
| `mono` | один знак на знакомест, работает в любом терминале |

Протокол графики kitty поддерживают kitty, WezTerm, Konsole, Ghostty,
foot и Apple Terminal. В этом режиме кадр уходит в окно как картинка и
занимает свой прямоугольник знакомест **без уменьшения** — тонкие линии
не рассыпаются, как в псевдографике. Размер знакоместа запрашивается у
терминала при запуске.

`graf.pas` чистит экран перед выходом, поэтому показывается **самый
наполненный кадр** — тот, что видел оператор, а не пустой результат.

## 9. Известные неясности

| Что | Состояние |
|---|---|
| Команда `0o353` (`К` в `НАЧГРАФ`), 3-4 на кадр | семантика не восстановлена, остаётся нераспознанной |
| Окружности | статья (стр. 43) утверждает, что окружности и дуги **не реализованы**; окружность в `graf.pas` получается последовательностью отрезков |
| Шкала размеров текста | реализовано как масштаб 1…4; шкала размеров терминала не сверена |
| Начертания кириллицы | взяты из ПЗУ знакогенератора КР556РТ5 терминала 15ИЭ, а не МС7401 |
| Межбуквенный интервал | шаг берётся по знакоместу, знаки ПЗУ разной ширины |
| Буква в приглашении ОС | «ЭВМ-3» приходит кодами `7C 42 4D`, в таблице ПЗУ позиция `0x42` — «Б», а ОС печатает «В»; остальные три буквы с таблицей совпадают |
